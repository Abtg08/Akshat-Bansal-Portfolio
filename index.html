Arcane
Production-grade AI capability & execution platform
A TypeScript platform for composing, deploying, and executing AI capabilities at production scale. Built for the gap between a working demo and a real agentic system — typed capability registry, execution tracing, structured output validation.
Problem
Most AI tooling stops at the prototype layer. Teams hit a wall moving from demo to production — no structured capability management, no reliable orchestration, no observability into what the agent actually did.
Architecture
TypeScript monorepo. Each AI skill is a typed, versioned unit in a capability registry. Execution engine handles retries, timeouts, and structured output validation. Designed for composability across multiple LLM backends.
Design goals
Strong typing throughout so AI output contracts are enforced at compile time, not discovered at runtime. Built observability hooks from the start — every execution is traceable.

2026 In Progress
Aegis Agent
Private, local-first Android AI agent
On-device Android AI agent that runs entirely locally — no cloud calls, no data leaving the device. Built in Kotlin for privacy-first AI assistance on mobile.
Why local-first
Most mobile AI assistants pipe everything to a remote server. Aegis keeps inference on-device — faster for latency-sensitive tasks, private by design, works offline.
Architecture
Kotlin Android app with on-device model inference. Agent loop handles task decomposition and tool invocation locally. Minimal-permission model — only asks for what it needs.
Key challenge
Balancing model capability against memory and battery constraints. The agent architecture needed to be interruptible and resumable without losing state.

2026 In Progress
Multi-Channel Data Platform
Unified cross-channel analytics pipeline
A GCP-native pipeline unifying data across marketing channels, CRM, and billing into a single analytics layer — powering attribution, ROI reporting, and campaign dashboards.
Problem
Marketing data lived in disconnected silos. Attribution and ROI were computed manually via spreadsheet merges — slow, error-prone, and impossible to audit.
Architecture
Python ingestion jobs pull from source APIs into GCS. Cloud Run workers normalize and load to BigQuery. dbt models compute attribution logic. Terraform manages all infra.
Key decision
GCS as raw landing zone for replay capability. Attribution logic lives entirely in dbt so analysts can iterate without touching ingestion code.
